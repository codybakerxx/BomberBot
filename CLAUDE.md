# BomberBot: notes for Claude

BomberBot is a top-down bomber battle game for the browser, built for phones. The owner directs the project and play-tests every change on a phone. Claude writes the code. Explain what you did in plain words, and lead with what changed for the player.

## Commands

```sh
npm install        # once
npm run check      # type-check, tests, build: run this before calling anything done
npm test           # tests only
npm run build      # writes dist/index.html, the whole game in one file
```

## Where things are

- `src/sim.ts`: all game rules. `src/swipe.ts`: the swipe pad and Movement sensitivity. `src/bot.ts`: the CPU players.
- `src/input.ts`, `src/render.ts`, `src/audio.ts`: input wiring, drawing, sound. `src/robot.ts`: how the robot is drawn (handed on through `render.ts`).
- `src/main.ts`: loop, title screen, Settings, the menu during a match, the score, layout. `src/lobby.ts`: the lobby. `src/setup.ts`: what the lobby and Settings choose, and saving it. `src/ui.ts`: the menus' controls. `src/title.ts`: the title screen's picture. `src/page.html`: markup and styles.
- Online play (`docs/ONLINE.md`): `src/net.ts` (the messages, input codes, checksums: pure), `src/room.ts` (one room: lobby, host, the match, run on the server; no network or clock of its own), `src/worker.ts` (the Cloudflare server: a Durable Object per room code), `src/online.ts` (the page's connection), `src/predict.ts` (the round on the page: the picture run ahead of the server so your robot moves at once; pure, the time is handed in). `wrangler.jsonc` says what is uploaded; GitHub uploads it on every push to `main`. The game is at https://bomberbot.bomberbot.workers.dev.
- Website and app (Settings › App): `src/app.ts` (home screen, notifications on the page), `src/push.ts` (signing and locking a notification), `Friends` in `src/worker.ts` (who gets them), `src/sw.js` (works offline, shows notifications). The icon: `drawIcon` in `src/title.ts`.
- `tests/`: checks for the pure modules, for online rooms (`room.test.ts`) and for how an online round feels over slow, uneven connections (`predict.test.ts`) (most build their arenas with `roundTicks: 0`, so the timer does not get in the way of what they check). `experiments/`: control-tuning simulations and CPU player matches, not part of the game.
- `docs/`: read `docs/CODE-GUIDE.md` first. `docs/ROADMAP.md` has the plan and every decision so far.

## Rules that must hold

1. `sim.ts`, `swipe.ts`, `bot.ts` and `net.ts` stay pure: no DOM, no `Math.random`, no clocks. The same seed and inputs must always give the same match, CPU players included (tests check it). Online play depends on it: the server runs `sim.ts` and `bot.ts`, and every page steps its own copy of the world with the server's inputs. Keep transcendental maths (`Math.sin`, `Math.atan2`...) out of `sim.ts` and `bot.ts`: engines may round them differently.
2. Rendering only reads the world. The rules never draw or play sound; they report events.
3. Game numbers are named constants at the top of `sim.ts`; pad numbers at the top of `swipe.ts`; CPU level settings in the `LEVELS` table at the top of `bot.ts`.
4. No image or sound files, and no new runtime dependencies. The game stays one self-contained HTML file. Beside it on the website, only what a phone needs to treat it as an app: the home-screen icons (`public/icon-*.png`, drawn by the game's own code with `tools/icons.py`), the manifest and the service worker (`src/sw.js`), written by `build.mjs`. The page plays without them (opened as a file).
5. Every screen works on an upright phone about 390 px wide, and sideways.
6. All art, code and sound are original. Do not copy from Bomberman or from `TommyBez/bomberman` (the project that inspired this one has no licence; it was used for ideas only).

- The game works with no connection once opened online (`sw.js`: the page network first, then the saved copy). Local only; Online says it cannot connect. Change `SHELL` in `sw.js` if the site's files change. The font is kept in a cache of its own that updates do not throw away.
- The website's icon is the title picture in a square (`drawIcon`; the owner's ask). The tab icon is drawn on the page; the home-screen PNGs come from the same code (`tools/icons.py`).
- Sound effects are layered and made in code (`voice`, `hiss` in `audio.ts`, through a compressor; upgraded at the owner's ask, November 2026). Same eleven ids and switches as before.
- Online play (built November 2026; `docs/ONLINE.md`): rooms by four-letter code, made from Title › Online; a link with `?room=CODE` opens the join panel; the lobby's share button sends that link. The lobby is the same lobby, with the other people in the room as player cards (`Guest.remote`; P1 the room's maker, then people in joining order, then CPU players). Each person picks their robot and presses Ready on their own screen. The host (whoever made the room) sets the CPU players and the rules; the others see the Match page read-only (`inert`). Only the host starts, and is asked first if someone is not ready. A room needs someone to play against, a CPU player or a person. The round cannot be paused: the menu opens and the round goes on behind it (the owner's choice). Only the host has Restart (the whole match, for everyone) and End match (everyone back to the lobby), and Next round, Rematch and Lobby at the end of a round; the others see who starts it. Everyone has Leave the room. Online, rounds are played out (no random winner when you are out). A dropped connection keeps its place and comes back into the round; a reload goes straight back in; a host gone 12 s hands the room on. The server runs the round and sends every page each tick's inputs; pages step their own copy of its world, with a checksum every half second (`worldHash`). What is drawn is a picture run ahead of that world (`predict.ts`; built after the owner found the first version laggy and jerky, and asked for it to be smooth): your robot moves the frame you press, presses say which tick they are for and the server keeps them until then, the page's clock runs ahead by the trip there and back (pings twice a second), and the other robots are drawn where the server last said, a few ticks back, never guessed at. Scores and results come only from the server's world. The menu shows the ping. Do not go back to drawing the server's world as it arrives, or to holding ticks back to step them evenly: that was the lag and the stutter. Your own setup and robot on this screen are kept aside while in a room and come back when you leave. Couch play is for this screen only, not online.

## Working on controls and feel
